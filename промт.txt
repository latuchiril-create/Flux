Improve the existing FLUX UI in the current project.

Do NOT redesign it from scratch.
Do NOT change the overall layout.
Do NOT break existing functionality.

Goal:
Make the interface feel cleaner, more premium, more deliberate, and less AI-generated / generic.

This is a Minecraft client / game-tool interface, NOT:
- a SaaS dashboard
- a mobile app
- a shadcn-style UI
- a Discord clone
- a generic futuristic AI dashboard

First inspect the existing UI implementation and reuse the current architecture/components.

Main issues to fix:
- too many borders
- too many rounded rectangles
- too many pills/badges
- too many icon buttons
- excessive nested cards
- excessive blue-gray colors
- too many visual indicators for the same state
- overly generic toggles
- excessive section headers
- repetitive spacing
- too much visual noise
- settings panel looks auto-generated
- color picker looks like a generic library component

Design direction:
- dark, dense, desktop game-client UI
- flatter surfaces
- fewer containers
- subtle borders
- small radii
- neutral grays
- one cold cyan/ice-blue accent
- compact spacing
- clear typography hierarchy
- actions shown on hover/context menu instead of permanently
- minimal decoration

Important rule:
If a state is already clear through position/background/text, do not also add border + glow + icon + badge + accent line.

Use approximately:
background: #080B0F
panel: #0C1015
surface: #10151B
border: rgba(145,170,190,0.08-0.12)
strong border: rgba(145,170,190,0.16-0.20)

Radii:
- main panels: 8-10px
- controls: 5-6px
- small controls: 3-4px
- list rows: 2-4px

SIDEBAR
- keep current structure
- simplify active category state
- use subtle background + small left accent line
- remove unnecessary active border/glow
- make inactive items neutral gray
- simplify profile/account block
- avoid SaaS-style subscription card look
- remove or de-emphasize the LIFETIME pill

MODULE LIST
- make rows flatter and cleaner
- primary content should be module name + toggle
- hide secondary actions until hover or context menu
- do not permanently show unnecessary icon buttons
- hotkey indicator only when a keybind exists
- selected row: subtle background + small left accent only

ICONS
- reduce icon count significantly
- do not place icons everywhere just for decoration
- avoid icon-inside-rounded-square patterns unless necessary

TOGGLES
- smaller and thinner
- less rounded
- no glow
- compact desktop/game-client style
- ON = accent track
- OFF = dark neutral track

RIGHT SETTINGS PANEL
- remove unnecessary cards and section headers
- setting rows should mostly be simple:
  label on left, control on right
- use spacing instead of borders to group content
- reduce repeated separators

TYPOGRAPHY
Use clear hierarchy:
- panel title: 15-16px semibold
- module name: 14px medium
- setting label: 13-14px regular/medium
- secondary: 12px regular
- section label: 10-11px semibold
Do not make everything bold.

COLOR SYSTEM
- mostly neutral dark grays
- cyan only for active/enabled/focus states
- no purple gradients
- no neon
- no glassmorphism
- no excessive glow

COLOR PICKER
Make it compact and native to FLUX.
Preferred structure:

Color ESP                          ×

[ SV field ]

[ hue slider ]

Opacity                        100%
[ opacity slider ]

[color swatch]  #75CDFF        copy

Remove:
- duplicate clipboard buttons
- excessive borders
- unnecessary checkerboard areas
- generic library styling

CONTEXT MENU
Make it compact and text-first.

Example:

Hitbox Customizer

Pin
Description

Copy settings
Paste settings

Reset settings

Use minimal separators.
Only keep icons where they add real value.

MODULE DESCRIPTION / TOOLTIP
Simplify it:

Hitbox Customizer                 ×

Displays customizable colored
entity hitboxes.

One background.
One border.
No "DESCRIPTION" badge.
No unnecessary decorative line.

SPACING
Avoid uniform spacing everywhere.

Use roughly:
- inside controls: 4-6px
- between related rows: 6-10px
- between groups: 16px
- between major sections: 24px

ANIMATIONS
Keep them subtle and functional:
- hover: 100-140ms
- toggle: 120-160ms
- popup: 120-160ms
- small opacity/translate transitions only

Do NOT add:
- bounce
- springs everywhere
- scaling effects
- glow animations
- animated gradients
- oversized shadows

IMPLEMENTATION RULES
- modify existing components, do not create a parallel UI
- preserve all existing functionality
- reuse shared components/styles
- centralize theme/design tokens if possible
- do not hardcode the same colors repeatedly
- do not make unnecessary architectural changes

VERY IMPORTANT:
Do not try to make the UI "more premium" by adding more visual effects.
Improve it mainly by removing unnecessary visual noise and improving hierarchy.

Work only on these areas first:
1. design tokens / shared UI primitives
2. sidebar
3. module list

Do NOT modify the right settings panel, color picker, context menu, or tooltip yet.

After editing:
- run the available build/tests
- fix any errors
- briefly summarize changed files and what was improved
